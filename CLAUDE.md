## Architecture (source/)
- `ReadinessApp.mc` – entry, `getGlanceView()` (:glance), onSettingsChanged → refresh.
- `ReadinessView.mc` – all drawing, cache (Storage "cache" {res,t}), pages 0..3:
  overview → factors → 7 days → 30 days. Refresh when data older than 30 min (10 min before noon,
  because Garmin first sends a provisional resting HR). `_small` / `_rowFont` = smaller vector fonts
  on hi-res AMOLED (w ≥ 360) via `smallFont()` with (:vector)/(:novector) annotations
  (VA4/VA4S exclude `vector` in monkey.jungle and beta.jungle).
- `ReadinessDelegate.mc` – START/tap next page, UP/DOWN (onNextPage/onPreviousPage), menu = refresh.
- `ReadinessGlance.mc` – (:glance), reads cached score only (no fetching): white title,
  "75 /87 High". Strings used in glance need `scope="glance"`.
- `DataFetcher.mc` – 9 × 7-day chunks (63 days) from
  `https://intervals.icu/api/v1/athlete/{id}/wellness?oldest&newest`, Basic auth `API_KEY:<key>`.
  Body Battery: `readBodyBatteryPeak()` = max since midnight (before 5:00 stored "bbPeak", else
  last 24 h); daily peaks saved in Storage "bbHist" (31 days) + backfilled from SensorHistory
  (last 3 days, 0–12 h) for the history.
- `ReadinessCalc.mc` – the model (weights/thresholds at top).
- `scripts/find-duplicates.ps1` – read-only finder of duplicate activities in intervals.icu.

## Score model
- Weights: Freshness 0.35, HRV 0.30, Sleep 0.20, Resting HR 0.15, Body Battery 0.20 **only when
  HRV score is null** (never together – BB is derived from HRV; deliberately kept that way).
  Missing factors → weights renormalised; needs ≥2 factors or freshness alone.
- Freshness = intervals.icu Form (CTL−ATL) as % of CTL, mapped
  [-50,-40,-30,-20,-10,0,10] → [10,25,45,60,75,85,95] (intervals.icu zones).
- HRV / RHR: today vs previous 27 days (needs 7 measured days = today + ≥6 previous, MIN_BASELINE 6;
  until then the row is grey, score "--", value shows days incl. today, e.g. "52 (2/7)"),
  z-score → 85 ± 25·z clamped 5..100 (**85 = your average**, footer says so). SD floor 5 % of mean (HRV), 1 bpm (RHR).
- Sleep: sleepScore, else hours [4,5,6,7,8] → [20,40,65,85,100].
- BB peak [30,50,70,85,95] → [10,40,70,90,100].
- **Morning score** = same factors but freshness from yesterday's CTL/ATL decayed one day
  (×exp(-1/42), ×exp(-1/7)). Shown as pale "/87" after the big number + light-grey ring segment, and
  a pale "Morning fresh / Ranna Sv. / Rano" row on factors – all only when morning and current
  score differ by > 2 points. History bars = morning score of each day.
- Bands/colours = Garmin Training Readiness, MIP palette only: ≥95 Prime 0xAA55FF, ≥75 High 0x00AAFF,
  ≥50 Moderate 0x55FF55, ≥25 Low 0xFFAA00, else Poor 0xFF0000.

## Decisions already made (don't re-propose without reason)
- Stress not used (derived from HRV, fluctuates). Garmin recovery time removed: Complications API
  needs a permission invalid for widgets (`ComplicationSubscriber` → "invalid for watch-app"),
  ActivityMonitor.timeToRecovery is missing on Venu 3/VA5, overlaps with freshness.
- No background fetching (glance shows last cached score).
- Labels: overview "Fresh", "BB", "RHR", moon icon for sleep; factors full labels when they fit
  ("Freshness", "Body Battery", "Resting HR"), fallbacks "Fresh", "Body Bat.", "RestHR".
  SK texts without diacritics ("Sviezost", "Spanok"). Version tiny above title on overview.
- Colours: page titles WHITE; morning values ("/87", morning row, ring segment) and bottom captions
  LT_GRAY; collecting HRV/RHR row and version DK_GRAY (owner found dark grey hard to read).

## Known gotchas
- SDK 9.3 strict typing: cast array elements before methods (`(x as Number).format`), static
  functions can't see class consts, avoid re-declaring the same loop var name in one function,
  makeWebRequest callback needs exact parameter types.
- Garmin's fonts: digits sit low in VCENTER; MIP displays need exact 64-colour palette values.
- Low scores are often caused by **duplicate activities in intervals.icu** (Garmin Connect + Strava /
  manual upload). Recommend keeping Garmin as the only activity source.
- Glances on a real watch may need the widget removed and re-added after the update that added glance.
